1. Which attack was hardest to defend against, and what does that tell you about the design of your agent?

	Out of scope creep was the hardest for me to defend against in this exercise. In the mobile world there are crossover terms that can create unexpected problems. For example a user to request to upgrade their plan (to a larger data amount) and also upgrade their device (purchase new equipment). Both can read the same by the agent causing it to trigger approval emails to be drafted for both requests when in reality we are not wanting to have this agent deal with equipment purchasing at all.


2. Your escalation trigger is the last line of defense between your agent and a mistake that reaches a real person. After running these tests, do you trust it? What would have to change before you would deploy this agent at work?

	In the scope of both the environment where this would be deployed and the scope of what is being asked of it, I would trust the agent. For this scenario we are not having the agent make any direct changes itself, rather it is identifying lines that could need to be actioned and bringing it to the mobile support agents attention. It is also only helping to get emails drafted but it is not asked to send anything out. Ultimately it is making all of the necessary pieces presentable for an agent to manually review so there is a final line of defense.
